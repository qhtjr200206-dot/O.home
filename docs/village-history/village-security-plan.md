# 마을 게임 설계 및 보안 검토 초안

상태: 미구현·배포 금지. 이 문서는 보안 검증이나 독립 보안 리뷰의 완료를 의미하지 않는다.

## 범위 및 설계

O.home의 별도 `/village` 경로와 자놀 메뉴를 후보로 한다. 기존 자관·캐릭터를 선택하고 장소, NPC, 세계관 및 시대를 설정한다. 시드 기반 맵, 서버 기준 시간의 자율 행동과 대사, 권한자의 이동, 선물, 시대별 메시지와 미니게임을 제공한다. 캔버스 및 터치 조작을 지원한다. 초기 동기화 후보는 서버 검증 폴링이다. `chuuns.com` 허브 연결과 배포 경로는 미확인이다.

방 비밀번호 검증 전에는 맵, 캐릭터, 메시지, NPC와 이벤트를 반환하지 않는다. 방 목록에 필요한 최소 공개 메타데이터와 민감 정보의 범위는 별도로 결정한다. 비밀번호 확인 후 발급하는 짧은 방 세션은 사용자·방·만료·비밀번호 버전에 묶고 모든 요청에서 검증한다. 비밀번호 변경이나 권한 회수 시 기존 접근을 무효화한다. 방 데이터는 브라우저 캐시나 공개 범용 콘텐츠 저장소에 두지 않는다.

## 위협과 필수 통제

- 방 격리: 방 ID 변경, 직접 DB 조회, 실시간 구독, 캐시 및 다른 방 쓰기 모두 차단한다. 관리자도 방 비밀번호를 거친다.
- 비밀번호: 검증값은 서버 전용 저장소에 salt를 사용한 느린 비밀번호 해시로 보관한다. 원자적인 공유 시도 제한을 방과 계정 등에 적용한다. 임의의 전달 헤더를 신뢰할 수 있는 IP로 취급하지 않는다. 로그에 비밀번호를 남기지 않는다.
- 로그인과 권한: Firebase 또는 Supabase 토큰을 서버에서 검증하고 신뢰 가능한 원본에서 관리자와 캐릭터 권한을 재조회한다. 캐릭터가 현재 방에 속하는지, 사용자가 현재 play 또는 edit 권한을 갖는지 매 명령 확인한다. 클라이언트의 사용자 ID나 관리자 여부는 신뢰하지 않는다. 기존 grant 필드의 서버 규칙 자체가 안전한지 먼저 확인한다.
- 방 생성: 일반 회원은 동시에 방 하나만 유지하고 삭제가 완료된 후 다시 만들 수 있다. 관리자는 무제한이다. 생성과 사용자별 슬롯 확보는 같은 트랜잭션으로 처리한다. 삭제 중에는 슬롯을 유지하고 정리 완료와 슬롯 해제를 원자적으로 처리한다. 관리자 권한 회수 시 기존 다수 방 처리 정책은 구현 전에 별도 결정한다.
- 삭제: 새 접근을 차단하는 active → deleting 전환과 세션 무효화를 원자적으로 수행한다. 재시도 가능한 정리 작업은 재사용하지 않는 방 인스턴스 ID에 한정하고 맵·캐릭터 상태·메시지·선물·세션·해시 등 관련 데이터를 삭제한다. 진행 중 쓰기 역시 트랜잭션에서 상태와 인스턴스를 재검사한다. 정리 실패 시 deleting과 슬롯을 유지한다. 백업 및 로그의 보존·폐기 정책도 출시 전에 정한다.
- 메시지·선물·이동: 발신자와 조작 캐릭터는 서버가 결정한다. 방 소속, 권한, 크기, 속도 및 이동 타일을 검증한다. 중복 명령은 멱등키와 원자적 상태 변경으로 처리한다. 자율 행동은 서버 시각과 단일 권위 상태를 기준으로 처리한다.
- 직접 접근: 방 비밀과 게임 상태는 Firebase에서는 Admin SDK 전용 및 Firestore 직접 접근 거부, Supabase에서는 서버 전용 접근과 RLS/권한 제한을 각각 설계하고 실제 규칙을 격리 환경에서 검증한다. 서비스 키나 관리자 SDK의 RLS 우회를 포함해 API마다 권한을 검증한다. 기존 비공개 자관, 캐릭터 및 공개 이미지 URL의 접근 범위를 별도 확인한다.
- 미적용 상태: 두 백엔드의 스키마·규칙·서버 설정이 준비되지 않으면 게임만 안전하게 비활성화하고 기존 사이트는 유지한다. 운영 DB 규칙과 SQL은 파일로만 준비하고 자동 적용하지 않는다.

## 검증 및 출시 차단 조건

Firebase 에뮬레이터와 Supabase 격리 환경 또는 검증된 테스트 더블 각각에서 직접 조회·쓰기, 다른 방과 캐릭터 조작, 틀린 비밀번호 및 병렬 반복 시도, 토큰 위조·만료·회수, 일반 회원의 동시 2회 생성과 관리자 판정을 재현한다. 테스트 더블만으로 실제 DB 규칙이나 RLS 적용을 증명할 수 없다. 메시지 위조·재전송, 변경된 비밀번호, 규칙 미적용 및 실패 경로도 확인한다.

독립 QA는 격리된 데이터로 가입·방 생성·접속·이동·상호작용·모바일 흐름을 브라우저에서 검증한다. 독립 보안 리뷰는 구현과 규칙, 공격 테스트 증거를 따로 확인하고 지적을 수정한 뒤 재검증한다. 두 백엔드의 안전한 방 격리가 입증되지 않으면 기능을 노출하거나 배포하지 않는다.

## 현재 확인된 근거와 미결 사항

- `src/lib/village/map.ts`와 `scripts/test-village-map.cjs`는 기존 미추적 작업이며 순수 맵 생성과 테스트만 있다. 방이나 보안 구현은 없다. 세계관 텍스트·NPC·캐릭터는 현재 맵 생성 입력이 아니다.
- `src/lib/charStore.ts`의 기존 play/edit grant 모델과 `src/app/rp/page.tsx`의 선택 로직을 참조하되 DB 규칙에서 권한의 진실성을 먼저 검증해야 한다.
- `firebase/firestore.rules`와 `src/lib/firebaseRules.ts` 사이 차이가 있어 실제 운영 규칙의 상태는 확인되지 않았다.
- Next.js 16 로컬 Route Handlers 문서에 따르면 핸들러는 app 디렉터리의 route 파일이며 기본적으로 캐시되지 않는다. 민감 응답의 캐시 방지와 인증은 별도 명시·검증한다.
- 이전 독립 설계 검토·도트 QA, 이번 보안 정책 구현 delegate 및 별도 hobby CLI 보안 리뷰는 모두 gpt-6.1-terra다. 구현 세션과 리뷰 세션은 분리됐지만 모델 다양성은 없다. 도트 구현 delegate는 미추적 파일을 다른 작업으로 오인해 중단했으며 팀장이 수정했다.
- `security.ts`는 서버 연결 없는 정책 함수이며 메모리 테스트 더블은 실제 DB 원자성이나 규칙을 증명하지 않는다. 독립 리뷰에서 다른 캐릭터의 grant 혼용 위험을 발견해 grant의 characterId 검사와 회귀 테스트를 추가했다. 서명 검증, 실제 관리자 판정, 해시·제한, DB 어댑터와 출시 전 독립 재검증은 남았다.
- 독립 설계 검토(별도 delegate, gpt-6.1-terra)는 방 ID 재사용 시 구 세션 부활, 삭제 중 쓰기와 슬롯 조기 해제 위험을 지적했다. 정책 함수에 인스턴스 ID와 삭제 중 접근 거부를 추가했으나 실제 저장소 트랜잭션·데이터 폐기는 아직 없다. 수정 후 독립 보안 재검증도 필요하다.
- 독립 도트 코드 검토(별도 delegate, gpt-6.1-terra)는 유효하지 않은 HEX 입력 중 저장하면 마지막 유효 색상이 저장됨을 지적했다. 경고가 표시되지만 저장 차단은 없으며, 실제 브라우저 재현과 UX 결정은 남았다. 두 검토 모두 별도 세션이나 같은 모델이며 시각 QA나 실제 서버 공격 테스트가 아니다.
- 도구 조사: Firebase 공식 Firestore Emulator 문서는 규칙 파일이 지정되지 않으면 에뮬레이터가 열린 규칙으로 동작할 수 있음을 경고한다(https://firebase.google.com/docs/firestore/security/test-rules-emulator). Supabase 공식 문서는 격리된 로컬 DB의 pgTAP 및 앱 수준 RLS 테스트를 제안한다(https://supabase.com/docs/guides/database/postgres/testing-row-level-security). 아직 도구 설치·라이선스 검토·실제 DB 테스트는 수행하지 않았다.

## 추가 독립 검토 기록

- 별도 delegate 보안 리뷰 `sa-0-639859c1`과 도트 QA `sa-1-300653eb`는 모두 gpt-6.1-terra로 수행했다. 서로 다른 모델이 아닌 독립 세션이다. 리뷰는 파일을 수정하지 않았다.
- 보안 리뷰: 현재 마을 정책 함수에는 인증 토큰 검증, 비밀번호 해시·시도 제한, DB 어댑터가 없고 메모리 더블은 실제 경쟁 조건을 입증하지 못한다. 캐릭터 grant 필드의 위조 가능성과 운영 규칙의 실효성을 별도 검증해야 한다. 삭제 및 인스턴스 기반 접근 폐기는 설계만 존재한다.
- 도트 QA: 기존 비교표를 시각 확인했으나 표정과 몸의 실루엣 차별성이 부족하다. 기존 32×40 그림의 확대에 일부 세부만 더한 구조이며 `size=100`의 출력도 80×100이므로 원본 100×100 이상 요구를 충족했다고 볼 수 없다. 색상 입력 오류 중 저장 시 마지막 유효 색상이 저장될 수 있으며 이전 인덱스의 외형도 바뀐다. 비교표는 정적 산출물이라 현재 코드와 일치 여부를 별도 확인해야 한다.
- 이번 검토에서 `node scripts/test-village-security.cjs`, `node scripts/test-village-map.cjs`, `node scripts/test-pixel-avatar.cjs`, `npm run build`는 통과했다. 빌드는 metadataBase 미설정 경고를 출력했다. 이 결과는 실제 DB 보안·원자성, 시각적 품질, 브라우저 전체 흐름을 입증하지 않는다. 지적 수정과 독립 재검증은 아직 이루어지지 않았으며 배포를 금지한다.

## 추가 팀장 확인 및 독립 검토

- 독립 보안 설계 세션 `sa-0-36d94524`와 도트 품질 검토 세션 `sa-1-777ca9cc`는 모두 hobby의 gpt-6.1-terra를 사용했다. 이종 모델 검토는 아니다. 보안 리뷰는 파일을 바꾸지 않았고 도트 검토는 래스터 비교 진단과 부정확한 주석만 수정했다.
- 보안 리뷰는 기존 규칙의 grant 변경과 Supabase 작성자 검증을 신뢰하기 전에 별도로 검증해야 한다고 지적했다. 운영 규칙은 확인하지 않았으므로 운영 취약점으로 단정하지 않는다. 토큰 검증, 방 API와 DB 경계, 원자적 방 삭제·재생성 및 공유 시도 제한은 여전히 미구현이다.

- 팀장이 도트·맵·비밀번호·보안 정책의 네 스크립트와 `npm run build`를 재실행해 통과했다. 빌드는 metadataBase 경고가 있었다. 실제 DB·브라우저 전체 흐름의 증거는 아니다.
